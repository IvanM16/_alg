# 習題 1：$2^n$ 計算方法比較與效能分析

本專案比較四種計算 $2^n$ 的方法，並評估在 $n = 100$ 情況下的執行效率與可行性。

## 演算法說明與比較

| 方法 | 實作邏輯 | 時間複雜度 | 空間複雜度 | $n=100$ 執行結果 |
| :--- | :--- | :--- | :--- | :--- |
| **方法 1** | `2 ** n` (內建次幂) | $O(\log n)$ | $O(1)$ | 瞬間完成 (< 0.0001 秒) |
| **方法 2a** | `power2n(n-1) + power2n(n-1)` | $O(2^n)$ | $O(n)$ | **算不出來** (計算次數達 $2^{100}$) |
| **方法 2b** | `2 * power2n(n-1)` | $O(n)$ | $O(n)$ | 順利完成 (約 0.0001 秒) |
| **方法 3** | 遞迴 + 查表 (Memoization) | $O(n)$ | $O(n)$ | 順利完成 (約 0.0001 秒) |

---

## 詳細分析

### 1. 方法 1 (內建次方 `2**n`)
* **優點**：底層使用 C 語言優化過的 Fast Exponentiation（快速冪）演算法。
* **結論**：速度最快，記憶體消耗最低。

### 2. 方法 2a (雙重遞迴)
* **問題點**：存在大量的**重複計算**。呼叫樹呈現完整的二元樹狀態，節點數量為 $2^{n+1}-1$。
* **$n=100$ 的狀況**：計算量為 $2^{100} \approx 1.26 \times 10^{30}$ 次。即使每秒計算 10 億次，也需要超過 **400 億年** 才能算完，因此在實際環境中**完全出不來（程式看似卡死）**。

### 3. 方法 2b (單一遞迴)
* **特點**：每次遞迴只呼叫自己一次，遞迴深度為 $n$。
* **結論**：時間複雜度降至 $O(n)$，在 $n=100$ 時能迅速算出結果。但若 $n$ 過大（如 $n > 1000$），會面臨 Python 的 `RecursionError`（超過最大遞迴深度限制）。

### 4. 方法 3 (遞迴 + 查表)
* **特點**：雖然邏輯也是 `power2n(n-1) + power2n(n-1)`，但透過字典（HashTable）記錄已計算過的子問題解答。
* **結論**：第二次遇到的子問題可以直接以 $O(1)$ 複雜度回傳，將原本 $O(2^n)$ 的指數型問題剪枝成 $O(n)$，成功解決方法 2a 算不出來的問題。
