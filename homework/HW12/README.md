 # 第 12 週習題：計算理論核心概念解說

---

## 一、 課程核心脈絡回顧

本週的計算理論（Theory of Computation）課程圍繞著一個核心問題展開：**「什麼是計算？電腦的能力邊界與極限在哪裡？」**

從 20 世紀初數學家希爾伯特提出「判定性問題（Entscheidungsproblem）」開始，哥德爾、丘奇、圖靈與喬姆斯基分別從**數學邏輯、函數、機器與形式語言**四個維度，奠定了現代計算機科學的理論基石。

---

## 二、 四大核心理論與程式對照

### 1. 喬姆斯基語法與有限狀態機（Chomsky Hierarchy & DFA）
- **理論概念**：
  喬姆斯基將形式語法分為四個層級（Type 0 到 Type 3）。其中最基礎的 **Type 3（正規語法，Regular Grammar）** 對應的計算模型是**有限狀態機（Finite State Machine, FSM）**。有限狀態機沒有額外的無限記憶體，只能依靠有限個「狀態」來記憶歷史資訊，因此無法處理需要無限計數的語法（例如任意深度的括號匹配 $a^n b^n$）。
- **程式實作對應（`DFA` 類別）**：
  我們實作了一個確定性有限狀態自動機（DFA），用來判斷輸入的二進位字串是否包含「偶數個 `1`」。機器只需要兩個狀態（`q_even` 與 `q_odd`）即可完成判斷。

### 2. 丘奇的函數與 Lambda 演算（Church's Lambda Calculus）
- **理論概念**：
  阿隆佐·丘奇（Alonzo Church）提出 **$\lambda$ 演算（Lambda Calculus）**，證明了僅靠「函數定義」與「函數應用（代換）」就能表達所有可計算的函數（即圖靈完備）。在純 $\lambda$ 演算中，函數都是匿名的，無法直接透過名稱呼叫自己來做遞迴，因此需要透過 **Y 組合子（Y Combinator）** 來尋找函數的不動點（Fixed Point），進而實現遞迴。
- **程式實作對應（`Z` 組合子與 `lambda_factorial`）**：
  在 Python 這類採用嚴格求值（Call-by-value）的語言中，我們使用 Y 組合子的變體 **Z 組合子**：
  $$Z = \lambda f. (\lambda x. f(\lambda v. x(x)(v)))(\lambda x. f(\lambda v. x(x)(v)))$$
  完全不使用 `def` 定義具名函數，純粹透過 `lambda` 表達式完成階乘 $n!$ 的遞迴計算。

### 3. 圖靈機（Turing Machine）
- **理論概念**：
  艾倫·圖靈（Alan Turing）提出了一種抽象的計算模型——**圖靈機**。它由一條無限長的紙帶（Tape）、一個讀寫頭（Head）、一組有限的狀態（States）以及狀態轉移規則表組成。**丘奇-圖靈論題（Church-Turing Thesis）** 指出：任何在直觀上「可有效計算」的問題，都可以由一台圖靈機來計算。
- **程式實作對應（`TuringMachine` 類別）**：
  我們模擬了一台單帶圖靈機，執行「二進位數加 $1$」的運算。讀寫頭先向右移動尋找最低位元（LSB），接著向左進行加法與進位處理（遇 `1` 改 `0` 繼續進位，遇 `0` 或空白 `_` 改 `1` 並進入 `HALT` 狀態停機）。

### 4. 不可判定性與停機問題（Halting Problem）
- **理論概念**：
  希爾伯特曾希望找到一種通用演算法，能判定任何數學命題的真偽（判定性問題）。然而，繼哥德爾提出**不完備定理**後，圖靈透過**對角線法（Diagonalization）**與自我指涉證明了**停機問題（Halting Problem）是不可判定的（Undecidable）**：不存在任何一個通用程式 `halts(P, I)`，能夠在有限時間內正確判斷任意程式 `P` 在給定輸入 `I` 時最終會停機還是陷入無窮迴圈。
- **程式實作對應（`HaltingParadoxDemo` 類別）**：
  展示圖靈構造的悖論機器 $D(P)$：若判定 $P(P)$ 會停機，則 $D(P)$ 故意進入無窮迴圈；反之則立刻停機。當把 $D$ 自身作為輸入執行 $D(D)$ 時，便會引發邏輯矛盾，證明通用停機判定器無法存在。

## 三、 如何執行程式

請確認環境中已安裝 Python 3.7 以上版本，並在終端機執行以下指令：

```bash
python week12_theory_of_computation.py
```
